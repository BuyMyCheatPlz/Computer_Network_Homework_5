# LCP 1 局域网聊天室应用协议

本协议由 Python 客户端和 C++17 服务端共同实现，适用于 IPv4 局域网。TCP 端口默认 45860，群聊组播地址为 239.255.42.99:45861，TTL=1。定向消息通过 TCP 发送给指定在线用户及发送者回显。组播群聊属于尽力交付，应用层使用 ACK 与 TCP 补发弥补丢包。

## 1 语法与边界

TCP 帧 = `uint32_be(N) || JSON_UTF8`。四字节无符号大端整数 N 只计算 JSON 的字节数，范围 1..32768；接收方循环读取精确字节数，处理拆包和粘包。UDP 数据报直接携带一份相同 JSON，不含四字节长度。拒绝重复键、非法 UTF-8、不支持的版本、额外或缺失的顶层字段。

```json
{"v":1,"id":"32位小写十六进制随机标识","type":"CHAT","ts":1793400000000,"body":{"mode":"all","targets":[],"text":"你好，世界"},"checksum":"64位小写十六进制SHA256"}
```

| 字段 | 类型与约束 | 含义 |
|---|---|---|
| v | 整数，固定 1，布尔值无效 | 协议版本 |
| id | 32 个小写十六进制字符 | 每个报文独立的随机标识 |
| type | 非空字符串，最长 40 字节 | 大写任务码，区分大小写 |
| ts | 0..9007199254740991 范围的整数 | Unix 毫秒时间戳，展示用，不作为身份凭据 |
| body | JSON 对象 | 任务参数 |
| checksum | 64 个小写十六进制字符 | 除自身以外五个字段的摘要 |

JSON 对象键递归按字典顺序排列，UTF-8 编码，不转义中文，不添加空格或换行；分隔符为 `,` 与 `:`。正文、用户名按 Unicode 码点计算字符数。正常报文的整数、字符串、布尔值、数组和对象可跨语言一致编码；业务字段不使用浮点数。

## 2 完整性算法

1. 接收报文后先校验语法、字段类型、范围和版本。
2. 复制对象，删除 checksum 字段。
3. 对剩余字段递归排序并紧凑序列化为 UTF-8 字节串 M。
4. 计算 `H = lowercase_hex(SHA256(M))`。
5. 将 H 与收到的 checksum 做等长逐字节比较；不相等时返回 BAD_CHECKSUM，不执行任务。

SHA-256 用于检出内容改变，不提供加密或发送者认证。能够修改数据并重新计算摘要的攻击者可以伪造报文。本课程实现没有 TLS/HMAC，也不声称能防主动中间人攻击；账号密码在 TCP 链路中为明文，账号文件中仅存随机盐和 PBKDF2 派生摘要。

## 3 客户端请求

| type | body 语法 | 状态与语义 |
|---|---|---|
| REGISTER | `{name:字符串,password:字符串}` | 未登录；创建持久化账号；用户名 1..20 个汉字、ASCII 字母数字、下划线或短横线；密码 6..128 字符；重复用户名返回 ok=false |
| LOGIN | `{name:字符串,password:字符串}` | 未登录；校验密码与在线唯一性；成功后进入在线状态并推送成员列表 |
| LOGOUT | `{}` | 已登录；注销当前会话，不删除账号，移除成员并清理其待确认消息 |
| MEMBERS | `{}` | 已登录；请求推送当前 ROSTER |
| CHAT | `{text:字符串,mode:"all",targets:[]}` | 已登录；非空白正文 1..2000 字符；服务端向当前在线成员组播，包含发送者 |
| CHAT | `{text:字符串,mode:"selected",targets:[用户名,...]}` | 已登录；1..64 个在线目标；去重后经 TCP 发送给目标及发送者；任一目标已离线则整条拒绝 |
| ACK | `{message_id:字符串}` | 已登录；确认一条群聊 MESSAGE；只清除当前会话用户名对应的待确认项；重复或未知 ACK 不产生业务效果 |
| PING | `{}` | 任意已连接状态；返回 PONG；客户端每 4 秒发送一次 |

客户端不得通过 body 指定可信发送者，服务端从连接的已登录会话取得 sender。最近 512 个合法任务请求的 id 保存在每连接的有界队列中，重复请求返回 REPLAY；这不是跨连接防重放机制。每连接每秒最多受理 120 个请求。未登录连接也计入最大 64 个 TCP 连接限制。

## 4 服务端响应

| type | 主要 body 字段 | 语义 |
|---|---|---|
| RESULT | request, action, ok, message | request 为原请求 id；action 为 REGISTER/LOGIN/LOGOUT/CHAT |
| RESULT 登录成功 | 上述字段及 name, group, udp_port, room_id | 客户端依据 group 和 udp_port 加入组播，room_id 标识本次服务端实例 |
| RESULT 聊天受理 | 上述字段及 message_id | 表示服务端受理，不能解释为所有接收者已展示 |
| ROSTER | members:[用户名,...] | 按用户名排序的完整在线名单，客户端替换旧名单 |
| MESSAGE | room_id,sender,text,mode,targets,recipients,request | recipients 是此条实际接收名单（含发送者）；request 为原 CHAT id；外层 id 用于 ACK 与去重，外层 ts 为服务端产生时间 |
| ERROR | code,message,request | 可读错误与稳定代码；若无法解析请求 id，request 为空串 |
| PONG | request | 心跳响应 |

ROSTER 在登录、注销、连接关闭时自动推送。每个连接写入加锁，避免多个线程同时发送造成帧交错；成员快照推送串行化，避免较旧名单覆盖新名单。

## 5 组播确认与补发

服务端对群聊记录 `(用户名, MESSAGE.id) → (当前单调时间+800ms, 原报文)`，然后向组播组发送一次。收到合法 MESSAGE 的客户端先校验 room_id 和 recipients，再发送 ACK，最后按 id 去重并展示。客户端保留最近 2048 个 MESSAGE.id。

后台线程每 100ms 扫描待确认表；800ms 后仍无 ACK 且对应用户在线时，通过该用户的 TCP 连接发送原 MESSAGE 一次，并删除待确认项。因此扫描抖动下触发时间通常为约 0.8..0.9 秒，仍受线程调度影响。客户端对 UDP 与 TCP 的重复副本只展示一次。禁用组播、网卡不支持组播或组播被网络设备丢弃时，客户端仍可通过 TCP 补发接收群聊。

TCP 补发依赖仍然有效的连接，没有离线队列、跨重启历史或严格全局顺序保证。大于链路 MTU 的 UDP 数据报可能发生 IP 分片；丢失任何分片均可触发 TCP 补发。TTL=1 限制组播跨路由传播；跨网段部署需额外设计。

## 6 异常与状态机

| code | 原因 | 连接处理 |
|---|---|---|
| INVALID_TASK | 报文合法，但 type 不在任务集合中 | 返回错误，继续受理其他请求 |
| BAD_PACKET | JSON、UTF-8、字段、版本、重复键或嵌套深度不合法 | 已知帧边界内丢弃当前报文并继续 |
| BAD_CHECKSUM | 摘要不匹配 | 丢弃报文，不执行业务，连接保留 |
| FRAME_TOO_LARGE | 帧长度为 0 或大于 32768；消息编码后过大 | 非法输入帧关闭连接；业务响应大小错误可恢复 |
| BAD_BODY | 参数类型、字符数、空白正文、mode 或 targets 错误 | 不执行业务，连接保留 |
| AUTH_FAILED | 用户不存在或密码错误 | 不登录，不区分两类原因 |
| ALREADY_ONLINE | 同一账号已在另一连接登录 | 当前连接保持未登录 |
| NOT_LOGGED_IN | 未登录执行需认证任务 | 拒绝执行 |
| STATE | 已登录时再次 REGISTER/LOGIN | 提示先注销 |
| NO_RECIPIENT | 定向目标为空或包含离线账号 | 整条消息拒绝，不部分发送 |
| REPLAY | 本连接请求 id 在最近 512 项内重复 | 不再次执行业务 |
| RATE_LIMIT | 本连接 1 秒窗口内超过 120 个请求 | 拒绝当前请求 |

状态转换：断开 → TCP 已连接未登录 → 登录成功在线 → LOGOUT 后已连接未登录。REGISTER 不自动登录。任何状态 TCP 关闭均清理资源；在线连接失联后服务器通过 EOF、读错误或约 15 秒接收超时移除成员。服务端发送超时为 5 秒，客户端正常通过心跳维持连接。
